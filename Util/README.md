# Util

Developer tools for OpenHyperAI. None of this is loaded by the game; run them with Node.js from the repo root.

| Tool | What it does |
|---|---|
| `split-console.js` | Splits Dota's `-condebug` console logs into one `game-NNN_<result>.log` per match plus a `.summary.txt` (scoreboard, every bot death, buildings, pushes, Roshan, lotus, script errors). Output goes to `Util/match-logs/` (git-ignored). `node Util/split-console.js [path\to\dota 2 beta\game\dota] [--out <dir>]` |
| `after-game.js` | One command after a game: re-splits the console (`split-console.js`), takes the newest game, and writes the review skeleton `Util/match-logs/game-NNN_review.md`: the build (`[OHA-BUILD]`, or the old `version` mapped to its commit range) and the PRs in the test build (`verify/test-build.json`), `verify.js check` output, script errors grouped by message, log spam (top `[OHA-*]` tags by peak lines per second), deaths and scoreboard, the mode flip-flop summary (`flip-report.js`), and the maintainer's comments on every tracked PR since the last review (`lastReviewAt` in `verify/tracker.json`). `node Util/after-game.js [path\to\dota 2 beta\game\dota] [--game NNN] [--no-split] [--no-mark] [--force]` (`--no-mark` keeps `lastReviewAt`; `--force` overwrites an existing review file). |
| `flip-report.js` | Mode flip-flops (#165) from `[OHA-FLIP]`, `[OHA-ROAMSTAT]` and `[OHA-HUNT]` lines: flip windows per 10 bot-minutes, top mode pairs, how long a mode lasted, the team_roam steps by the team roam rule that won them (snipe, hunt-carry/lane, ...; capped or not) with their previous / next mode, team roam activations by rule with the share that switched itself off (`huntSelfOff`), lifted its cap (`capLift`) or got a last hit (snipe), and the Clinkz / Nyx Assassin / Spirit Breaker hunt traces. `after-game.js` includes it. `node Util/flip-report.js <game.log> [...]`; `--self-test` checks the parser on `Tests/data/flip_report_sample.txt` (CI runs no Node: run it after changing the tool; `Tests/test_roam_stats.lua` pins the same file on the Lua side). |
| `release-notes.js` | Draft release notes: one line per PR merged into main since the last `v*` tag (title and change-log entry headings from the PR body), in the sections Patch, New, Fixes, Project, plus a hidden list of what was left out (reverts, PRs reverted later, PRs with only `cleanup` entries). The `/release` skill tidies the draft. `node Util/release-notes.js [--from <tag>] [--to <ref>] [--version vX.Y] [--json]` |
| `build-info.js` | Writes `Customize/build_info.lua` (git-ignored): commit, branch, dirty, build time and `version = "<commit date>-<sha>"`, which `Customize/version.lua` prefers over its static number and the game prints as `[OHA-BUILD]`. Run by the git hooks after checkout, commit, merge and rebase (`pre-commit install --install-hooks` installs them); run it by hand before a test game if you edited files since the last commit, so `+dirty` is current. `node Util/build-info.js` |
| `export-bots.js` | Copies only the bot scripts (tracked `.lua` at the root and under `BotsLib/`, `FuncLib/`, `Customize/`, read from git) into Dota's `vscripts/bots`, after checking every literal `require`/`dofile` target is in the copy (#177). A tracked `.lua` file in any other folder stops it until the folder is listed in `RUNTIME_DIRS` or `NOT_RUNTIME_DIRS`; `--test-game` names the edited and new (uncommitted) bot scripts it left out. Default: `origin/main` as committed, for a Workshop upload (`/prepare-workshop`). `--test-game`: `HEAD` plus the working-tree `Customize/general.lua` (test lineup) and a `Customize/build_info.lua` for that commit (`/prepare-game`). Never writes through a symlink/junction, inside a worktree or into a folder with `.git`, and deletes only files it wrote before (list in `.git/oha-export-bots.json`). `node Util/export-bots.js [--test-game] [--ref <rev>] [--dest <dir> \| --dota <game/dota>] [--dry-run] [--remove] [--force]`; `--self-test` checks it (CI runs no Node: run it after changing the tool). |
| `issue-prs.js` | `node Util/issue-prs.js <N> ...` starts work on issues: branch `<fix/feat/docs/chore>/issue-<N>-<slug>` from `origin/main`, one signed empty commit, a draft PR with the template and `Refs #N`. Without numbers it only copies each issue's priority label to its PRs and lists untriaged issues. `[--dry-run]`; needs `gh` logged in. |
| `item-builds/check.js` | Item-build second opinion (#38): compares each hero's item lists with Stratz data per position (needs `STRATZ_TOKEN` in `.env`): the latest week and all ranks, or `--week YYYY-MM-DD` / `--bracket DIVINE_IMMORTAL`. Writes `Util/item-builds/report.md` (git-ignored): items rare in the data, common items we never buy, common items with a low win rate. Report only, never edits a build. `node Util/item-builds/check.js [hero ...] [--week YYYY-MM-DD] [--bracket <rank>] [--refresh]`. |
| `skill-builds/gen-fixture.js` | Writes `Tests/data/hero_abilities.lua`, every hero's ability slots from the game files (ultimate, hidden, innate, not learnable, max level, linked abilities), which `Tests/test_skill_builds.lua` checks every hero's level-up list against (#45). Run it again after a patch that changes abilities: `node Util/skill-builds/gen-fixture.js <folder with scripts/npc from pak01_dir.vpk> [patch name]`. |
| `verify.js` | In-game verification tracker for PRs not tested in a game yet (`Util/verify/tracker.json`, git-ignored). `add <pr>` imports the PR’s "How to verify in game" list, `check <game.log> --game NNN` counts each item’s log tags with sample lines, `set <pr> <item or all> pass/fail/skip [note]`, `show`, `done <pr>`, `lineup [--suggest [--write]]` (test-lineup slots in `Customize/general.lua`: keep / can free, and placing heroes pending items need), `expect <pr> <item> "<rules>"` and `heroes <pr> <item> a,b` (auto pass/fail and hero needs), `mute-suggest <pr>` (OHA_MUTED entries for proven logs). |
| `test-build.js` | Builds the local integration branch `test/next` = `origin/main` + every PR in the verify tracker (+ `--with <branch>`), skipping and listing PRs that conflict, writes `Util/verify/test-build.json` and switches the working tree to it, carrying `Customize/general.lua`. `node Util/test-build.js [--dry-run] [--no-switch] [--with <branch>]`. Never pushed. |
| `luabal.js` | Rough block-balance check for Lua files (`function`/`if`/`do` against `end`). Compare with the committed file rather than trusting the number. `node Util/luabal.js <file.lua> ...` |
| `boots-check.js` | Lists hero positions whose build ends up with more than one pair of boots (outfits expanded). `node Util/boots-check.js` |
| `urn-builds.js` | Regenerates `URN_BUILDS` in `FuncLib/systems/item_strategy.lua` (which positions' builds carry Urn / Spirit Vessel / Essence Distiller) from the hero files. Run after any build change: `node Util/urn-builds.js --write`. |
| `item-builds/generate.js` | Whole item builds from Stratz (#38): rebuilds every hero's buy list for every position (starting items, boots, core and late items) from the week's purchase data, ordered by purchase minute, and walks each list the way `item_purchase_generic.lua` buys it (six slots, sell pairs, parts) before writing it. `node Util/item-builds/generate.js [hero ...] [--write] [--fetch] [--week YYYY-MM-DD] [--patch 7.42] [--explain] [--report <file.md or .json>]`; without `--write` it is a dry run. `--write` rewrites the build blocks in `BotsLib/hero_*.lua`, the generated sell pairs and `URN_BUILDS`; run StyLua on `BotsLib` and the tests afterwards. `pins.json` holds the decisions the data must not override (each with its reason), `status.json` what was done per hero and position (own data / a neighbour position's data / follows another position / kept, with the reason), `items.json` the item facts from the game file (`game-items.js <items.txt>` rewrites it and `Tests/data/item_recipes_742.lua` after a patch). For another week: move `cache/raw/` away, then `--fetch --week <day> --patch <patch>`. The rules are in `lib/build.js` (what goes in a list) and `lib/sim.js` (the walk; `Tests/test_item_build_sim.lua` is its Lua twin). |
| `role-weights/` | Rebuilds `FuncLib/data/hero_pos_weights.lua` from Dotabuff's 7-day All Pick meta table (`dotabuff_7d.txt`). `gen.js` holds the formula and the source URLs; `supcheck.js` lists heroes drafted as pos 4/5 whose support build is really a core build. |
| `hero-review/` | The 2026-11-16 review of all 127 heroes against the patch: the brief the reviewers followed, their eight reports, and `gen.js`, which builds the `hero-review.html` report page. |
| `meta-builds/` | The 2026-11-17 item / skill build review against Dotabuff: the data (most played items and most picked skill per level for all 127 heroes), `build.js` to make one review file per hero, the reviewers' brief and their eight reports. |

`match-logs/`, `verify/`, `role-weights/rows.json`, `hero-review/hero-review.html` and `meta-builds/heroes/` are generated and git-ignored.
