# Util

Developer tools for OpenHyperAI. None of this is loaded by the game; run them with Node.js from the repo root.

| Tool | What it does |
|---|---|
| `split-console.js` | Splits Dota's `-condebug` console logs into one `game-NNN_<result>.log` per match plus a `.summary.txt` (scoreboard, every bot death, buildings, pushes, Roshan, lotus, script errors). Output goes to `Util/match-logs/` (git-ignored). `node Util/split-console.js [path\to\dota 2 beta\game\dota] [--out <dir>]` |
| `after-game.js` | One command after a game: re-splits the console (`split-console.js`), takes the newest game, and writes the review skeleton `Util/match-logs/game-NNN_review.md`: the build (`[OHA-BUILD]`, or the old `version` mapped to its commit range) and the PRs in the test build (`verify/test-build.json`), `verify.js check` output, script errors grouped by message, log spam (top `[OHA-*]` tags by peak lines per second), deaths and scoreboard, and the maintainer's comments on every tracked PR since the last review (`lastReviewAt` in `verify/tracker.json`). `node Util/after-game.js [path\to\dota 2 beta\game\dota] [--game NNN] [--no-split] [--no-mark] [--force]` (`--no-mark` keeps `lastReviewAt`; `--force` overwrites an existing review file). |
| `build-info.js` | Writes `Customize/build_info.lua` (git-ignored): commit, branch, dirty, build time and `version = "<commit date>-<sha>"`, which `Customize/version.lua` prefers over its static number and the game prints as `[OHA-BUILD]`. Run by the git hooks after checkout, commit, merge and rebase (`pre-commit install --install-hooks` installs them); run it by hand before a test game if you edited files since the last commit, so `+dirty` is current. `node Util/build-info.js` |
| `issue-prs.js` | `node Util/issue-prs.js <N> ...` starts work on issues: branch `<fix/feat/docs/chore>/issue-<N>-<slug>` from `origin/main`, one signed empty commit, a draft PR with the template and `Refs #N`. Without numbers it only copies each issue's priority label to its PRs and lists untriaged issues. `[--dry-run]`; needs `gh` logged in. |
| `item-builds/check.js` | Item-build second opinion (#38): compares each hero's item lists with OpenDota item popularity and, with `STRATZ_TOKEN` in `.env`, Stratz per-position data. Writes `Util/item-builds/report.md` (git-ignored): items rare in the data, common items we never buy, common items with a low win rate. Report only, never edits a build. `node Util/item-builds/check.js [hero ...] [--refresh]`. |
| `verify.js` | In-game verification tracker for PRs not tested in a game yet (`Util/verify/tracker.json`, git-ignored). `add <pr>` imports the PR’s "How to verify in game" list, `check <game.log> --game NNN` counts each item’s log tags with sample lines, `set <pr> <item or all> pass/fail/skip [note]`, `show`, `done <pr>`, `lineup [--suggest [--write]]` (test-lineup slots in `Customize/general.lua`: keep / can free, and placing heroes pending items need), `expect <pr> <item> "<rules>"` and `heroes <pr> <item> a,b` (auto pass/fail and hero needs), `mute-suggest <pr>` (OHA_MUTED entries for proven logs). |
| `test-build.js` | Builds the local integration branch `test/next` = `origin/main` + every PR in the verify tracker (+ `--with <branch>`), skipping and listing PRs that conflict, writes `Util/verify/test-build.json` and switches the working tree to it, carrying `Customize/general.lua`. `node Util/test-build.js [--dry-run] [--no-switch] [--with <branch>]`. Never pushed. |
| `luabal.js` | Rough block-balance check for Lua files (`function`/`if`/`do` against `end`). Compare with the committed file rather than trusting the number. `node Util/luabal.js <file.lua> ...` |
| `boots-check.js` | Lists hero positions whose build ends up with more than one pair of boots (outfits expanded). `node Util/boots-check.js` |
| `urn-builds.js` | Regenerates `URN_BUILDS` in `FuncLib/systems/item_strategy.lua` (which positions' builds carry Urn / Spirit Vessel / Essence Distiller) from the hero files. Run after any build change: `node Util/urn-builds.js --write`. |
| `role-weights/` | Rebuilds `FuncLib/data/hero_pos_weights.lua` from Dotabuff's 7-day All Pick meta table (`dotabuff_7d.txt`). `gen.js` holds the formula and the source URLs; `supcheck.js` lists heroes drafted as pos 4/5 whose support build is really a core build. |
| `hero-review/` | The 2026-11-16 review of all 127 heroes against the patch: the brief the reviewers followed, their eight reports, and `gen.js`, which builds the `hero-review.html` report page. |
| `meta-builds/` | The 2026-11-17 item / skill build review against Dotabuff: the data (most played items and most picked skill per level for all 127 heroes), `build.js` to make one review file per hero, the reviewers' brief and their eight reports. |

`match-logs/`, `verify/`, `role-weights/rows.json`, `hero-review/hero-review.html` and `meta-builds/heroes/` are generated and git-ignored.
